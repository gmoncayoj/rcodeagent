# Security and privacy

Report suspected vulnerabilities privately to **gamarramoncayoj@gmail.com**. Do not post access tokens, encrypted credential files, personal datasets or private conversations in public issues.

rcodeagent sends the selected editor context, enabled read-only attachments, conversation context and instruction to the authorized service when a request is submitted. Local chat history includes message text and attachment content. Exports are local files; users control their later distribution. UI language selection does not change the prompt or response language.

OAuth credentials are encrypted locally; the encryption key is kept in the operating system credential store. Neither API keys nor Codex CLI are required. Loopback-only networking does not protect against other applications running as the same operating-system user.

Normal is chat-only; server checks block editor and console effects. Auto requires explicit activation and remains bound to the selected R target. Exact patches are prepared before the final editor ID/path/full-content check. Conflicts and IPC failures revoke Auto. Explicit Auto permits changes only to the selected R target, with syntax and grant checks. Auto is not stored in history. A temporary Viewer return within the same Job can preserve the grant after revalidation. Code is never saved automatically. Console submission requires a current explicit imperative bound to the exact code, request, Viewer owner and target snapshot. Explicit Auto requests, including new code and package installation, do not need a second confirmation. Quoted, negated and conditional instructions do not authorize execution. Other classified administrative operations require an exact preview and one-use confirmation, as explicitly retained by the user. Package installation is excluded from that classifier. Explicit eligible context recapture preserves an already enabled Auto with a fresh generation and cancels the old worker; failed captures and unrecaptured conflicts still revoke it. These checks do not sandbox arbitrary R or prove that unrecognized code has no side effects. A fixed public sendToConsole operation executes with the user session permissions. Pending console input blocks submission, but the check is not atomic and does not detect every interactive R state. The user explicitly accepted native queueing; Chat Stop and closing the assistant cannot withdraw submitted code. No automatic Environment inspection, output collection or project-wide file crawling is available.

This is a local-first research tool with experimental service integration. Supported account access, inference, forced refresh, OS credential storage and native RStudio behavior need separate verification. Version 0.1.0 names the current deliverable; it does not assert security certification, CRAN acceptance or universal platform compatibility.

The 2026-10-17 audit identified a medium-severity client-origin issue affecting Viewer recovery. The author approved repairs: admission now checks the exact loopback Host, the Origin when present and a private per-Job capability before initializing or transferring chat state. Missing or incorrect capabilities and foreign origins were rejected in isolated Chrome tests, including a foreign HTTPS site with local-network access granted. The same Job still recovered its synthetic draft and Auto state. A native RStudio compatibility check of this new admission control remains pending; the finding is not represented as fully verified/closed. See docs/validation/1.0.0.md.

OAuth renewal validates replacement tokens, lifetime and returned plan scope, serializes refreshes with an interprocess file lock and uses recoverable encrypted-file replacement. Terminal errors remove unusable tokens; temporary failures preserve credentials. Disconnect attempts revocation through the trusted issuer's discovered endpoint, then removes local tokens even if auxiliary metadata cannot be saved. If remote revocation is unconfirmed, the UI tells the user to disconnect the app in ChatGPT Settings. These paths were tested with synthetic credentials and mocked transport, not a real account.

OSV was queried again on 2026-10-24 for 58 installed CRAN dependencies (runtime and test closure), with a successful positive control and no matching advisories. See docs/validation/dependencies-osv-2026-10-24.json. This is a dated known-advisory check, not proof of safety; system libraries, vendored components, IDE and manual-generation tooling are outside that query. Native Linux/macOS behavior and real provider renewal/revocation remain unverified.

The 2026-10-24 prepublication review of the unpublished 1.0.0 candidate found one medium-severity issue in the additional administrative-confirmation control. Version 0.1.0 fixes the skipped function-default arguments and verifies the exact confirmation boundary with classifier and server regressions, an independent code review and full source/installed suites. See docs/validation/administrative-confirmation.md and docs/validation/github-readiness.md. The original private Codex Security report remains sealed outside the repository; the repair is separate evidence, not a new exhaustive audit. Arbitrary R execution remains unsandboxed and the documented native/provider/platform limits remain.
