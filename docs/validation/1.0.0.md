## October 18 complete-deletion regression

The user reported OAuth disconnection/reconnection and a format failure when asking Auto, in the original Spanish, “borra toda la línea 1 del script abierto”. The same message was reproduced by validating a `modify` proposal with `code = ""`: the package required nonempty code and confused deletion with an absent proposal. This reproduced an edit-validation failure; it neither proved an OAuth failure nor validated the whole OAuth lifecycle.

An empty string is now accepted only for modification of the captured document/range. The interface recognizes proposals by action and snapshot. The historical Editor interface showed deleted lines and an empty-context notice, while still requiring review bound to that proposal. Auto could clear its authorized target. Empty generated scripts, NULL/vectors/numbers, empty explanations and invalid syntax remained rejected. Permission, range, ID/path/full-content and conflict checks remained enforced. Viewer recovery preserved the empty proposal but discarded its previous approval.

Worker errors use the root condition without ANSI sequences, correcting the appearance of the message shown in the user's screenshot. Tests are in `test-empty-edit.R`, `test-request-errors.R` and `test-viewer-recovery.R`. Remote transport and editor interactions were mocked; corresponding worker checks used real callr processes. `empty-edit.json` retained 32 checks added for this regression. `browser.json` and `empty-edit-review-*.png` recorded Auto, manual review and Viewer return with an empty proposal.

After reinstalling and testing, the user confirmed, in the original Spanish, “ahora funciona perfecto”. This is human evidence of the tested native deletion flow, not validation of renewal/revocation, every Viewer path or Linux/macOS. Historical insertion into empty buffers was not reused as proof of deletion. This correction added no dependencies and did not change OAuth, PDF manuals or the logo.

## Approved repairs

- **Viewer:** admission before chat initialization or checkpoint claim. Exact loopback Host and a random 256-bit per-Job capability; a present Origin must match exactly. The private fragment is absent from HTTP queries, history and exports. Initial Shiny input tracing is disabled. Viewer, native Background Job, the 60-second/2-second/30-minute timing and Addins recovery remain.
- **OAuth:** validate tokens, expiry and plan permission after renewal; remove credentials for terminal errors and retain them for temporary failures. filelock serializes reading/rotation across processes. Encrypted writes use staging, rollback and recovery. Identity/client metadata without tokens supports reconnection. Disconnect attempts remote revocation and removes local tokens despite auxiliary metadata failures, reporting unconfirmed revocation. Credential POSTs do not follow redirects.
- **Editor:** final ID/path/full-content comparison after patch preparation. Conflicts revoke Auto and block writing. Captured selections, syntax checks and one native insertText operation remain. Generated code was neither saved nor executed by this historical edit flow.
- **Diff/patches:** numbered removed/added lines with context and expandable resulting code. Exact patches are bound by SHA-256 to source text and result. No fuzzy application or arbitrary model paths. Confirmation belongs to the displayed proposal and does not survive Viewer disconnection as permission. The model proposes context text; the server derives the patch.

OAuth handling was compared with [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) and [Errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery). Local tests do not establish actual provider acceptance.

## Independent review and security

Original sealed audit: `10fc4cf0-29d1-4a5d-8738-690c5e4e5b4b`; medium CWE-346 finding `csf_4ea6e74d3191358905562a27`. Draft and Auto transfer to foreign HTTPS with local-network permission had previously been reproduced. Its canonical artifacts remain outside the repository and were not modified.

Prior independent investigation covered the Shiny boundary, followed by independent review of the candidate diff. The reviewer found two regressions: auxiliary metadata saving could prevent token removal, and preparing the patch after checking the editor could overwrite a manual change. Failing tests reproduced both; repairs and regressions passed. Preparing the patch before the final read removes that avoidable delay. The public editor API does not provide atomic comparison/write; elimination of every possible cross-process race is not claimed.

**Repairs implemented; comprehensive security verification remained pending** (recorded as `blocked` because native compatibility testing was unavailable). The trigger and alternative inputs were blocked in-browser and legitimate recovery worked. The new admission control still needed actual Addins recovery inside RStudio. The finding was not marked closed in the workbench and no certification was asserted. OSV does not cover all system libraries, the IDE, vendored components or Python tooling.
