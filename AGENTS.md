## Build, Test, and Development Commands

Use R >= 4.2.0. From the workspace, install the working package and launch it:

```r
install.packages(c("remotes", "testthat"))
remotes::install_local(".", upgrade = "never")
rcodeagent::rcodeagent() # Run interactively inside RStudio
```

## Security & Architecture Constraints

The user rejected both the external-browser experiment and a custom RStudio build. The current 0.1.0 renumbers the unpublished 1.0.0 implementation built from 0.5.7, keeps Viewer and restores a temporarily detached chat via the Addin, preserving the last message, attachments, model, effort, synced draft, target and previous Auto ON/OFF state. The grant lives only in the same Job's memory, never in histories or exports. Revalidate the saved target ID/path/full content before preserving Auto; keep the captured selection range, not the current cursor selection. Conflicts, missing targets or IPC failures revoke Auto. New Jobs and new/history-resumed chats still start with Auto OFF. Do not modify the installed IDE, replace Posit Assistant files, patch namespaces, or invoke undocumented helpers. A native custom tab/fork is historical rejected context, not an accepted plan.

`R/background.R` launches the Viewer app with native `rstudioapi::jobRunScript`, never blocking `runGadget` in the console. Keep `importEnv=FALSE`, `exportEnv=""`, loopback-only Shiny and native IPC; do not add an arbitrary-code bridge. Editor availability in the child must use `isAvailable(child_ok=TRUE)`. Reuse an idle/running job, reject unknown states, and cancel workers/OAuth on disconnect without replaying requests. Keep the 2-second reload grace before recording suspension and the 60-second initial-connection deadline; stop a disconnected Job after 30 minutes, with a generation check so stale timers cannot stop a recovered session. Only explicit Close ends the app immediately. `R/viewer-state.R` holds the one-owner, one-use recovery checkpoint in memory. No queries/writes before the client restores its inputs; never write while detached. Test actual Viewer return separately from mocks/local workers.

Maintain native OAuth without requiring Codex CLI or an API key fallback. Never log tokens. Require consent for additional file access, edits, and execution. Preserve document conflict checks and syntax validation. Treat the prototype as experimental until real authentication and editor workflows pass.

`R/viewer-auth.R` admits clients before initialization/checkpoint claim: exact loopback Host, exact Origin when present, and a private per-Job fragment. Never trace the initial Shiny inputs or persist this capability in histories/exports. `R/auth-state.R` serializes OAuth lifecycle operations using filelock and stages encrypted replacements with rollback/recovery. Auxiliary identity-metadata failures must not block revocation or invalid-token cleanup. Never follow redirects when posting credentials. `R/edit-patches.R` builds bounded exact line patches on the server; it does not accept arbitrary model-supplied file paths or fuzzy patches. Bind manual confirmation to the reviewed proposal, never restore approval after Viewer detach, prepare the patch before the final ID/path/full-content comparison and perform only the existing native insertText call.
